Source wiring only. Seed Vault has not been played or accepted. No accepted Light report, save or coordinator hash exists yet. Do not run either browser mode until the coordinator gives a new resource slot. Keep the whole Act 1 replay unchanged.

The entry point is `bun tools/play-seed-vault.mjs /absolute/path/to/coordinator-config.json`. The configuration must contain:

- `mode`, explicitly `preflight` or `earned`.
- `handoff`, containing `reportPath`, `savePath` and the coordinator's exact `acceptedSHA` for the accepted Light result.
- `out`, a new empty evidence directory, `dist`, a separate built Seed runtime, `buildRevision`, and an exclusive assigned `port`. Ports 5795 and 5796 and `dist-gallery-resume-hud` are rejected. The build revision must include bee fix `4fc25cf4`.
- `selection`, with `weapon` and `fitting`. Supported fittings are `spring_hilt` and `glow_cap`. The inherited selected weapon must be tier 2.
- `routes`, with nonempty arrays for `bench`, `stair`, `door`, `roots` and `home`. Each point contains numeric `x`, `y`, `z`. Routes are explicit authored input, not an approval. Every point uses the existing realtime driver's arrival guard. The home route ends within two units of the accepted Light checkpoint position. Outdoor routes and heights remain unproven. No example coordinates are supplied to imply otherwise.
- For `earned`, `preflight` and `review` paths for the previously collected interior manifest and human image review. `earnedReview` names the separate human review of actual earned captures, required before acceptance.

The CLI validates the complete accepted Light report and its evidence hashes before creating a session, report, process or game action. Gallery saves, diagnostic saves and guessed hashes cannot pass. Missing configuration exits with usage. The generic `tools/chapter.mjs` invocation alone cannot supply this session; use the dedicated entry point above.

`preflight` starts its own server and shared Chrome launcher only after the handoff and configuration gates. It creates diagnostic new-game fixtures inside the actual Seed Vault room at its memory stone, with fight/key flags set only for presentation. Each sample carries the image and raw-cost hashes. All raw frames must meet the quality table. There are no default approvals.

A person must inspect the captures and write the review file. Its shape is `{ "pass": true, "images": { "/absolute/image.png": "actual SHA256", "...": "..." } }`, with exactly the manifest's image paths and hashes. Do not generate `pass: true` from successful capture. Earned preflight revalidates the review, raw cost frames and full emitted runtime hashes against the source revision and build revision. Changes require fresh preflight and review. The build revision is a supplied build provenance claim; the coordinator must establish that the emitted build came from it. The ancestry check alone cannot prove which source produced arbitrary emitted bytes.
